Forge clients are translated with Fluent (`.ftl`) files in five locales. The browser clients embed the files and switch the language without a reload. This page is checked against the `i18n/` directories, `quench_ui::i18n` and `forge-shell`.

## Locales and files

Every service with a UI keeps its files in `services/<name>/service/i18n/`:

```text
en-US.ftl   de-DE.ftl   es-ES.ftl   fr-FR.ftl   pl-PL.ftl
```

`en-US` is the first entry of every `LOCALES` table and so the fallback. Services with the five files: conveyor, gantry, gatehouse, gauge, sage, switchboard, warehouse, workbench. The files of one service have the same set of keys (checked: no key missing or extra in any of the four translations of any of these services).

| Service | Message keys per file |
|---|---|
| conveyor | 145 |
| gantry | 118 |
| gatehouse | 230 |
| gauge | 116 |
| sage | 129 |
| switchboard | 153 |
| warehouse | 212 |
| workbench | 72 |

Daybook is different: `services/daybook/service/i18n/` is empty (only `.gitkeep`); `services/daybook/web/i18n/` holds five files of 17 keys each, the keys of the top bar only. The file says "The app itself has no translations yet": the screens of `daybook-app` are English. Hoist and Forklift have no `.ftl` files. `libs/forge-ui/examples/gallery.ftl` is the gallery example's file.

## How a client loads them

The app crate embeds the files at compile time and builds an `I18n`:

```rust
const LOCALES: [(&str, &str); 5] = [
    ("en-US", include_str!("../../service/i18n/en-US.ftl")),
    ("de-DE", include_str!("../../service/i18n/de-DE.ftl")),
    ("es-ES", include_str!("../../service/i18n/es-ES.ftl")),
    ("fr-FR", include_str!("../../service/i18n/fr-FR.ftl")),
    ("pl-PL", include_str!("../../service/i18n/pl-PL.ftl")),
];
let i18n = Rc::new(I18n::new(&LOCALES, &setup.language).expect("the translations parse"));
```

(`services/workbench/app/src/live.rs`; Daybook's equivalent is in `daybook-web/src/browser.rs` with `../i18n/*.ftl`.) A parse error is a panic at start, so a broken file is found at once. Because the files are embedded, a changed `.ftl` needs a rebuild of the wasm module.

## The `I18n` API (`quench_ui::i18n`)

| Item | Behaviour |
|---|---|
| `I18n::new(files: &[(&str, &str)], initial: &str) -> Result<I18n, ParseError>` | parses each `(language, ftl text)`; the first entry is the fallback |
| `t(id) -> String` | message in the current language |
| `tr(id, args: &[(&str, Value)]) -> String` | with arguments; a message missing in the current language is taken from the fallback; an unknown id comes back as the id itself, so a missing translation shows on the page |
| `language()`, `set_language(&str)`, `languages()` | current language (a signal-backed value, so views follow it), switch, list |
| `Value` | `Number(f64)` or `Text(String)`; `From` for `i32`, `u32`, `usize`, `f64`, `&str`, `String` |
| `plural_category(language, n)` | CLDR plural category (`Zero|One|Two|Few|Many|Other`) |

Supported Fluent subset: messages, `{ $var }`, references to other messages, number and string literals, `NUMBER($n)`, and selectors on plural categories or exact numbers (`{ $n -> [one] ... *[other] ... }`). Attributes, terms and other functions are skipped.

## Choosing and keeping the language

* The initial language is `quench_ui_web::browser::storage_get("language")`, default `en-US`. The browser storage key is `q:language`.
* The top bar (`forge_shell::topbar`) shows the language picker with flags (`forge_shell::flag("pl-PL")` is the regional-indicator pair for `PL`); picking calls `Bar::on_language`, which the app wires to `I18n::set_language` and to `Request::Language(code)`; the web crate stores it with `storage_set("language", Some(code))`.
* `shell.js` copies the `qlocale` cookie (set by the server-rendered pages and by gatehouse's pages) into `q:language` when the app has none, and sets cookies `qlocale` and `qlocale_chosen` when a `#language` select changes, so the language follows the person across services.

## Key conventions

* A file starts with `# required` followed by the header keys: `header_label` (the service's name), `footer_label` (`© 2026 Paweł Walus — Order of Devs`), `locale_label`, `theme_label`.
* Keys are `snake_case` and prefixed: `ui_` for everything shown by the client, grouped by screen (`ui_home_*`, `ui_board_*`, `ui_issue_*`, `ui_login_*`, `ui_admin_*`, `ui_account_*`, `ui_models_*`, `ui_vllm_*`, `ui_storage_*`, `ui_col_*` for table columns, `ui_status_*`); `api_error_*` for texts the API returns (60 in the services that use them).
* Gatehouse maps its domain errors to keys (`RealmError::i18n_key`: for example `AlreadyExists` gives `ui_admin_error_exists`, `LastAdmin` gives `ui_admin_error_last_admin`); the page shows the key's translation.
* Section comments use the form `# ── Home ──...` .
* Every file must define the shell keys the top bar uses: `locale_label`, `ui_dashboard_button`, `ui_home_button`, `ui_logout`, `ui_profile_edit`, `ui_theme_mode`, `ui_theme_palette`, `ui_theme_toggle`, `ui_user_menu`, and `ui_palette_green|teal|blue|purple|rose|orange` (and, in the existing files, `ui_theme_light` / `ui_theme_dark`).
* Plural messages use selectors, not string concatenation.

## Adding a key or a language

A key: add it to `en-US.ftl` and to the four other files in the same commit; use it as `t.t("ui_...")`. Rebuild the module (`scripts/web.sh`).

A language: add `xx-XX.ftl` to the service's `i18n/`, add it to `LOCALES` and to the `languages` list of the `Bar` in the app's `live.rs` (for Daybook the `LANGUAGES` constant), and copy the shell keys. `plural_category` needs a rule for the language to pick correct plural forms; check it in `quench-ui`.

## Testing

Screen tests mount the app with a language in `Setup` and read the text back; the `I18n` parser has its own tests in `quench-ui` (`tests/unit/i18n_tests.rs`). No test in Forge compares the key sets of the five files: the equality stated above was checked by a one-off script.
