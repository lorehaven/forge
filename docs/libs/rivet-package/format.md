The `.rivet` format, byte-exact as produced by `PackageBuilder` and accepted by `Package::read`.

## Container

* File name by convention: `<name>-<version>.rivet` (`file_name`). The version may contain `+` build metadata.
* The file is a **zstd** stream (`quench_archive::zstd::compress`) of a **tar** (`quench_archive::tar::Builder`). No directory entries are written; readers skip directory entries.
* Every tar entry is a regular file at the archive root level of the overlay: paths are relative, `/`-separated, no `./` prefix.
* Entries are sorted by path (byte order of the `String`, `BTreeMap` order). Header values for every written entry: kind regular file, mode `0644` (octal), uid `0`, gid `0`, mtime `0`, no link target (`quench_archive::tar::Header::file`).
* Identical input gives byte-identical output with a fixed zstd library version.

## Required and optional files

| Path | Required | Content |
|---|---|---|
| `rivet.toml` | yes | manifest (below); generated by the builder from the `Manifest` value |
| `overlay.yaml` | yes | overlay entry point; opaque to this crate |
| `SHA256SUMS` | yes | digests of every other file |
| anything else | no | the overlay's own files at their relative paths (templates, `values.toml`, secrets, ...); opaque to this crate |

`VALUES_FILE` (`values.toml`) is only a constant; the crate does not treat it specially. What Riveter does with other files is in the Riveter CLI documentation.

## `SHA256SUMS`

Text, UTF-8, one line per file other than `SHA256SUMS` itself, sorted by path, each line exactly:

```text
<64 lower-case hex digits><space><space><path>\n
```

Example (from a package with `overlay.yaml` and `templates/a.yaml.j2`; digests abbreviated):

```text
3c6e...e1  overlay.yaml
b0a4...7f  rivet.toml
9d12...05  templates/a.yaml.j2
```

Reader rules (`parse_sums`): blank lines are ignored; each other line is split at the **first** two-space sequence; the digest must be exactly 64 ASCII hex digits (upper case accepted and lower-cased); a path listed twice is an error; every file in the archive except `SHA256SUMS` must be listed and match; a listed path missing from the archive is an error. A line using a single space or `*` binary marker is malformed (`malformed line`).

## `rivet.toml`

Top-level tables: `[package]` (required), `[requires]`, `[meta]`, `[[deployment]]`. Unknown top-level keys are ignored on read (the top-level struct has no `deny_unknown_fields`), but `[package]`, `[requires]`, each `[[deployment]]` and each `[[deployment.also_stops]]` reject unknown keys.

| Key | Type | Required | Default | Rule |
|---|---|---|---|---|
| `package.name` | string | yes | | DNS-1123 label (`is_valid_name`) |
| `package.version` | string | yes | | semver incl. build metadata (`0.4.0+b123`); `1.0` is rejected |
| `package.description` | string | no | none | one line (no `\n`), at most 500 bytes |
| `package.namespace` | string | no | none | DNS-1123 label |
| `requires.riveter` | string | no | none | a semver requirement (`>=0.3`) |
| `requires.packages` | array of string | no | `[]` | each `name` or `name <requirement>` |
| `meta` | table | no | empty | free-form, never interpreted |
| `deployment[].name` | string | yes | | DNS-1123, unique within the manifest |
| `deployment[].description` | string | no | none | not validated |
| `deployment[].resources` | array of string | yes | | non-empty; each `deployment/<label>` or `statefulset/<label>` |
| `deployment[].default` | `"running"` or `"stopped"` | no | `"running"` | |
| `deployment[].conflicts_with` | array of string | no | `[]` | each a DNS-1123 label, not the deployment's own name |
| `deployment[].also_stops[].selector` | string | yes | | non-blank after trim, must not start with `-` |
| `deployment[].also_stops[].namespaces` | array of string | no | `[]` | not validated |

Serialisation (`to_toml`) omits `requires` when empty, `meta` when empty, `deployment` when there are none, and `None` or empty optional fields.

Example:

```toml
[package]
name = "forge"
version = "0.4.0+b123"
description = "one line"
namespace = "forge"

[requires]
riveter = ">=0.3"
packages = ["postgres >=1", "redis"]

[meta]
anything = "carried, never interpreted"

[[deployment]]
name = "inference"
description = "one line"
resources = ["deployment/sage", "deployment/switchboard"]
default = "running"
conflicts_with = ["training"]

[[deployment.also_stops]]
selector = "app=vllm"
namespaces = ["ml"]
```

A package that declares no `[[deployment]]` is, to Gantry, one deployment named after the package (Gantry's behaviour; not implemented in this crate).

## Validation rules

`Manifest::validate`, in order; the first failure is returned as `PackageError::Manifest`:

1. `package.name` is a DNS-1123 label. Text: ``name `N` must be a lowercase DNS-1123 label (a-z, 0-9, `-`; at most 63 characters)``.
2. `package.version` parses as semver.
3. `package.namespace`, if present, is a DNS-1123 label.
4. `package.description`, if present, is at most 500 bytes with no `\n`.
5. `requires.riveter` parses as a version requirement.
6. Each `requires.packages` entry passes `parse_package_requirement`.
7. For each deployment, in order: valid name; not declared twice; `resources` non-empty; each resource `deployment/<name>` or `statefulset/<name>` with a valid name; `conflicts_with` does not contain its own name; each `conflicts_with` entry is a valid name; each `also_stops.selector` is non-blank and does not start with `-`.

This crate does not check that the named workloads exist in the overlay; `riveter pack` does.
